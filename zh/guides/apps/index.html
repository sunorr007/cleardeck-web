按应用查看与管控

从每个应用看它在网上做了什么、访问记录怎么看，以及怎样把一条记录变成一条规则 —— 只对一个应用生效，还是对所有应用生效。

仪表盘上的总数告诉你发生了什么，应用视图告诉你是谁干的 —— 还能把一条连接 变成一条规则。这是御流里最需要动手的部分，所以这篇从「怎么进去」一直讲到 「规则怎么加才不会白加」。

怎么进去

应用列表不是底部标签。底部只有仪表盘、模块、设置、工具四项，没有别的。 进应用视图要从仪表盘走，有两条路：

  • 点活跃连接统计格。
  • 点应用 Top 5 右边的更多。

两个入口打开的是同一个界面，界面里有实时活动和访问历史两个页签。活跃连接 进到实时这一侧，更多则打开历史列表。

实时活动与访问历史

列表分成两个页签，看每一行的文案就知道自己在哪个页签：

页签 English 每行显示
实时活动 Live %1$d active connections —— 这个应用此刻开着的连接数
访问历史 History %1$d attempts · %2$d blocked，以及「最后一次是多久以前」

实时是这一瞬间的快照，应用开、关连接时会跟着变。历史是累计的：它数的 是这个应用在本次防护期间做过的每一次尝试，不论有没有被拦。想知道某个应用 「一直在干什么」而不是「此刻在干什么」，就看它。

认不出来的那些行

有几行没有应用名。当系统没法把一条连接归到某个已安装应用时，这一行会显示 未知来源，或者在 Android 能给出用户 ID 但给不出应用时显示 uid <数字>。 这些不是故障，而是御流如实报告 Android 告诉了它什么、没告诉它什么，而不是替它 编一个名字。

应用详情

点一个应用会打开它的详情页。最上面是三个统计格，用的词和大盘一致：

统计格 English 含义
上传 Upload 本次防护期间这个应用发出去的字节数
下载 Download 它收到的字节数
已节省 Saved 拦掉这个应用的连接大约省下的流量，算法与仪表盘相同

下面是一张拦截构成卡片 —— 说明是这个应用的连接的哪一类规则拦下的。在 地址（URL）层而不是域名层被拦下的条目，会带一个深度标记。有它，说明这条 拦截来自地址匹配，而不是名单上的某个域名 —— 这也是深度解析确实在干活的直接 证据。见深度解析。

访问记录

访问记录是这张应用做过的每一次尝试，可以展开。每条记录就是一条连接，带 主机名和结果，还有 —— 这是最有用的地方 —— 两个按钮：拦截和放行。 被动的一条记录，就是靠这两个按钮变成主动的规则。

列表上方有筛选和排序两项：

控件 English 选项 中文
筛选 All / Blocked only / Allowed only 全部 / 仅拦截 / 仅放通
排序 By time / By site 按时间 / 按站点

按站点会把同一个站点的多条记录并成一行。当一个应用反复联系同一个主机、 你想看它到底会联系哪些站点时，这个视图最合适。按时间则适合追单独一件事 —— 「我刚打开它之后发生了什么？」

把一条记录变成规则

点拦截或放行不会立刻落规则，而是先弹出应用到…，给你两个选择：

选项 English 什么时候选它
仅这个应用 This app only 这个主机只对这个应用有意义，比如它自己的遥测
所有应用 All apps 这个主机你不希望这台手机上的任何应用去连

所有应用范围很宽：它不只管你正在看的这个应用，对所有应用都生效，而且会变成 一条全局规则。拿不准的时候，仅这个应用是更稳的默认值，范围更大的那条以后 随时可以补。你为这个应用加的规则也会出现在它的详情页上，可以在那里用移除 一条条删掉。

不论选哪个，加进去的规则都会出现在模块页的 我的拦截与放行里。这张卡刻意做成不能一键关掉，因为它是你自己的决定，不是 内置名单。这里还适用两条优先级：

  • 同一个主机上，放行规则赢过拦截规则。你放行了某个主机，任何模块都 不能再把它拦回来。
  • 你写的规则赢过内置模块，永远。

这两条都是有意的：内置名单只是默认值，你的决定排在它们前面。

导出，以及一句提醒

这个页面上也有导出记录，可以只导出某一个应用的记录。格式、列名和完整步骤见 导出访问记录。

先导出再停

记录会随防护关闭而清空。这里看到的任何东西，只要你打算留下 —— 写反馈、自己 存档、以后还想照着加规则 —— 都要在点停止防护之前先导出。隧道一断，本次的 记录就没了，也找不回来。
